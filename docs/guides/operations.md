# Создание кампаний и восстановление

[Все документы](../README.md)

Команды выполняются из корня проекта.

## Создание кампаний

Дополнительно задаются `KEITARO_DOMAIN_ID`, `KEITARO_GROUP_ID`,
`KEITARO_TRAFFIC_SOURCE_ID`, `CAMPAIGN_NAME_PREFIX` вида `test_surname_` и
`KEITARO_CREATION_PROFILE` — путь к локальному JSON-файлу. Адаптер проверяет
существование выбранных справочников перед созданием.

Профиль содержит `version: 1`, `origin`, `verified: true`, а также объекты
`geo` и `fallback` с **проверенными на этом экземпляре** полями создания
потоков. Для `geo` нужна схема `redirect`, реальный `action_type`, редирект
на `https://google.com` и country-фильтр с заменяемым значением `{{country}}`.
Для `fallback` — схема `landings` и реальный `action_type`. Состав офферов,
название, тип, порядок, состояние и идентификатор кампании задаёт адаптер по плану use case.
Не переносите синтетические payload из тестов в рабочий профиль.

Публичная схема недостаточно определяет `action_payload`. В репозитории есть
[пример профиля](../../deploy/keitaro-profile.example.json) по результатам проверки
Keitaro 11.5.0. Скопируйте его в `.local/keitaro-profile.json`, укажите свой origin
и проверьте контракт по [спецификации 001](../specs/001-keitaro-contract.md).
Пример содержит `verified: false`, поэтому сам по себе не разрешает создание.
`verified: true` — явная отметка исполненной проверки, а не способ её выполнить.

Для Compose файл подключается read-only. Например, сохраните локальный
дополнительный файл конфигурации в `.local/compose.profile.yaml`:

```yaml
services:
  app:
    environment:
      KEITARO_CREATION_PROFILE: /run/keitaro-profile.json
    volumes:
      - ./.local/keitaro-profile.json:/run/keitaro-profile.json:ro
```

Запуск: `docker compose -f compose.yaml -f .local/compose.profile.yaml up -d app`.
Пути дополнительного файла разрешаются относительно основного `compose.yaml`.
Файл профиля и реальные настройки не входят в Docker-образ или Git.

## Работа редактора

- **Обновить экран** перечитывает локальную БД. **Fetch Streams** получает
  состояние Keitaro; при несохранённых в Keitaro изменениях сначала нужны
  Cancel или Push.
- **Add / Remove / Bring Back / закрепления** меняют сохраняемый в БД черновик.
  Доли рассчитываются на сервере; активная сумма равна 100%.
- **Cancel** восстанавливает базовое состояние. **Push to KT** сверяет поток
  с исходным снимком и отправляет только поле `offers`. Внешний конфликт
  сохраняет черновик для решения оператором.
- **Проверить в Keitaro** выполняет чтение после неизвестного результата.
  **Продолжить операцию** доступно при доказанном отказе или частичном создании.
  Известные ID сохраняются; уже созданные объекты проверяются до новых записей.
- **Ручная проверка** требует подтверждения, что внешний запрос завершён,
  и заметки о проверке. Принятие текущего состояния потока сбрасывает черновик.

После таймаута запись не повторяется автоматически. Кампания остаётся
зарезервированной до сверки; прежнее состояние Keitaro само по себе не
доказывает, что запрос не будет применён позднее. После перезапуска незавершённые
операции также требуют сверки. При потере ответа браузер сохраняет ключ команды
в `sessionStorage` текущей вкладки и предлагает проверить результат.

Создание идёт по этапам: выключенная кампания → два потока → сверка → активация.
Частичный результат остаётся виден в журнале, автоматического удаления нет.
Предварительная и завершающая сверки не являются атомарной условной записью
Keitaro: одновременное внешнее редактирование может потребовать ручного решения.

Интерфейс рассчитан на доверенное локальное окружение и не содержит системы
пользовательских учётных записей. Публикация сервиса в интернет не входит в
текущий вариант развёртывания.
