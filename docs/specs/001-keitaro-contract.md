# Контракт интеграции с Keitaro

Дата исследования: 18 ноября 2026 года.
Статус: на Keitaro 11.5.0 проверены чтение, импорт, создание, Push и конфликт.
Границы живых проверок — в таблице K-01–K-05 и [отчёте](../guides/validation.md).

## Подтверждено опубликованной схемой

В [официальном OpenAPI](https://admin-api.docs.keitaro.io/openapi.json)
указаны база `/admin_api/v1` и заголовок `Api-Key`.

| Назначение | Метод и путь |
| --- | --- |
| Кампании | `GET/POST /campaigns`, `GET/PUT /campaigns/{id}` |
| Потоки кампании | `GET /campaigns/{id}/streams` |
| Поток | `POST /streams`, `GET/PUT /streams/{id}` |
| Офферы | `GET /offers`, `GET /offers/{id}` |
| Справочники | `GET /domains`, `GET /groups?type=campaigns`, `GET /traffic_sources` |
| Возможности потоков | `GET /stream_filters`, `GET /streams_actions` |

Создание кампании требует `name` и `alias`; запрос поддерживает `domain_id`,
`group_id`, `traffic_source_id`, `type`, `state`. Связь оффера описывается
`offer_id`, целочисленным `share` и `state`. Фильтр использует `name`, `mode`
и массив строк `payload`. Отдельного `/offers/search`, условий `If-Match`
и заголовка идемпотентности в этой схеме нет; это не доказывает их отсутствие
во всех версиях сервера. [Схема API](https://admin-api.docs.keitaro.io/openapi.json).

Документация указывает, что PUT сохраняет поля, отсутствующие в запросе.
Поэтому наш адаптер обновляет только `offers`, не отправляет копию всего потока.
[Семантика Admin API](https://docs.keitaro.io/en/development/admin-api.html).

Keitaro разделяет forced, regular и default-потоки; default обрабатывает трафик,
не подходящий другим потокам. Это соответствует выбранной схеме regular-геопоток
и default-поток офферов при ротации кампании по позиции.
[Порядок обработки потоков](https://docs.keitaro.io/en/campaigns-and-streams/streams.html).

## Результат обращения к целевому экземпляру

При первоначальном обращении без авторизации наблюдались:

| Ресурс | Наблюдение |
| --- | --- |
| `/admin` и `/admin/` | HTTP 403, HTML с контейнером формы входа, загружаемой JavaScript |
| `/admin_api/v1/campaigns` | HTTP 401, JSON |

После разрешения владельца выполнен вход через Chromium. Статус 403 страницы
входа не препятствует загрузке формы и авторизации. Версия экземпляра — 11.5.0.
Для интеграции использован существующий Admin API-ключ текущего пользователя;
ключ из общего appConfig не подходит для Admin API. Новые ключи не создавались.
Управление ключами описано в [документации Keitaro](https://docs.keitaro.io/en/team-management/admin-api-keys.html).

Авторизованные GET campaigns, offers, domains, groups, traffic_sources,
stream_filters, streams_actions и потоков кампаний возвращают 200. Параметры
limit/offset списка кампаний проверены: страницы различаются и соблюдают limit.

На фактических потоках подтверждены: строковый action_payload для HTTP-редиректа,
country-фильтр с mode=accept и массивом кодов стран, схема landings с
offer_selection=before_click, привязки offer_id/share/state и технические поля
id/stream_id/created_at/updated_at. На существующих кампаниях наблюдались геопотоки forced и поток офферов
default. Отдельной записью проверено создание выбранной приложением схемы
regular/default; фактический переход посетителя по геомаршруту не проверялся.

Через локальное приложение проверены поиск оффера, импорт тестовой кампании,
закрепление 100% в локальном черновике, Cancel и повторный Fetch. Геопоток
доступен только для чтения, поток офферов — для редактирования. Интерфейс
проверен в Chromium на 1440px и 390px без JS-ошибок и переполнения.
После разрешения владельца через приложение создана отдельная тестовая кампания.
Подтверждены regular-геопоток с country-фильтром и HTTP-редиректом, default-поток
с оффером, ID справочников и сохранение параметров источника. Итоговая ссылка
сформирована из подтверждённых домена и alias.

На её потоке проверены замена массива `offers`, архивирование после Fetch,
Bring Back и реальный Push. Повторы Create/Push с тем же ключом вернули прежний
результат. Внешнее изменение потока вызвало конфликт и сохранило черновик.
После проверок тестовая кампания отключена.

Важная особенность 11.5.0: PUT только с `offers` переводит пустой `action_payload`
потока `landings` из `null` в `""`. Прочие поля сохранились. Это различие
нормализуется при семантическом сравнении; для `redirect` сравнение строгое.

Создание новых офферов недоступно учётной записи (403). Живая запись проверена
с одним существующим оффером, без изменения его глобального объекта.
Многовариантное распределение и сетевые сбои проверены на синтетическом gateway.

Настройки и доступы находятся только в игнорируемых локальных файлах. Для живого
origin создан отдельный Compose-проект и локальная БД; прежняя БД сохранена.

Полная публичная схема и результаты обращений сохранены только локально
в `.local/research/`. SHA-256 полученной схемы:
`4d08aaa2377716852cf10abb7497948f875041af6f0edd6d177c5b3cbdbac2f8`.
Сырые ответы целевого сервера не должны становиться тестовыми fixtures без очистки.

## Решения адаптера

- Поиск по имени — фильтрация каталога `/offers` на backend с коротким кешем.
  Поиск по ID может использовать отдельное чтение. Неподтверждённые параметры
  поиска и пагинации для этого метода не отправляются.
- Запись состава — полное желаемое множество активных привязок в поле `offers`.
  Архив приложения в запрос не включается; удаление определяется отсутствием
  привязки в составе. Замена массива подтверждена на разрешённом тестовом потоке.
- Успешный HTTP-ответ недостаточен для завершения операции: приложение
  сверяет фактическое состояние. Необходимые поля обязаны совпасть семантически.
- Неизвестные режимы, поля привязок, отключённые привязки и неоднозначные ответы
  не исправляются автоматически; редактирование такого потока блокируется.
- Схема не используется как основание обещать атомарную условную запись или
  автоматический безопасный повтор POST после timeout.

## Статус проверок совместимости

| ID | Результат | Граница проверки |
| --- | --- | --- |
| K-01 | Подтверждено: авторизованные GET и импорт, версия 11.5.0 | Для другого экземпляра проверяется заново |
| K-02 | Созданы regular/default, сохранены country-фильтр и HTTP-редирект | Фактический геопереход посетителя не проверен |
| K-03 | PUT заменяет `offers`; пустой массив удаляет привязку, Push возвращает её с целым весом 100 | Несколько офферов проверены синтетически; нормализация пустого payload учтена |
| K-04 | Подтверждены чтение после записи, повтор команды приложения и конфликт | Обрыв живого запроса не имитировался; атомарная условная запись не подтверждена |
| K-05 | Подтверждены справочники, параметры источника и итоговая ссылка созданной кампании | Ссылка проверена по конфигурации, без перехода и регистрации клика |

В публичной схеме есть пробелы: например, ответ потока содержит `action_payload`,
а `StreamObject`, использованный запросом создания, его не перечисляет.
Ответ кампании также не описывает все данные привязки домена. Поэтому эти поля
нельзя угадывать по названию: нужны документация экземпляра или наблюдение его
фактических запросов/ответов. Для нового экземпляра без
проверенного профиля адаптер возвращает ошибку совместимости до первой записи.

Доступ и существующая конфигурация проверяются чтением. Создание и любые
пробные записи агентом требуют отдельного разрешения владельца
на конкретные тестовые объекты.
Проверки не блокируют реализацию домена, локального хранения, API приложения
и интерфейса с подменённым gateway.
